# 中文公开稿

## 文章骨架

单个 H1，开头单列项目完整地址，用行内代码避免自动链接，随后放中文封面。主章节 H3，小节 H4。

1. **一、概览**：项目是什么、解决什么、适合谁；从组件职责和数据流解释框架，再展开一个有辨识度的设计。不要直接用某个案例替代项目介绍。
2. **二、部署与开始使用**：集中说明系统、架构、硬件、磁盘、内存／显存、驱动与依赖；给出安装方式、必要配置、具体入口、第一次操作及预期输出。GUI 项目可先写安装包，源码方式保留短命令。官方没有统一最低配置时不要编造，说明模型相关条件与本次设备。
3. **三、实战与使用案例**：先展示实际运行的官方代表性示例；没有合适官方示例时采用自拟任务。保留有素材支撑的外部使用案例，必要时补充自己的扩展应用。通常约占文章五分之一；多个有效案例可以扩展，不能挤掉介绍与上手。
4. **四、结语**：说明适用场景、接入方向和影响选型的判断，不复述全文或添加金句。

用户提供的既往文章可作为结构和语气参考；样本不提供当前项目事实、作者经历或操作授权。

## 读者共鸣与切入

定标题前，先用一句内部简报写清“谁在什么场景遇到什么麻烦，有什么感受，项目具体接走哪段工作”。标题、开头和案例围绕这个需求组织，避免只列项目名、技术栈和功能。共鸣可以来自重复劳动、挫败、自嘲或期待，也可以来自想做出某种成果的兴奋，不固定套用焦虑或亏损。

例如，股票研究工具面对的读者可能熟悉亏损后的懊恼、追涨杀跌的自嘲，以及每天翻行情和消息的疲惫。可以借股民听得懂的调侃进入话题，再落到整理自选股、每日报告、保留判断依据。调侃不等于“所有散户一直亏钱”的事实断言，研究工具也不据此包装成回本或盈利保证。

用户给出的标题、梗图和圈内表达优先保留其意图，顺着语境使用，不生硬解释笑点。用户明确采用的标题或原图文案可有口语、反问与夸张语气，作为通用“正文少问句、少词藻”的局部例外；不扩展为全文的营销腔。正文仍直接说明功能、过程与结果，不虚构读者经历或作者感受。

## 信息密度与语气

- 直接对读者说话，删除“我为你”“本稿由……”等委托或制作语言。
- 用动作、输入、输出和条件组织段落。说明改了哪段文本后重做哪段音频，少写“赋能创作、提升效率”。
- 直接陈述功能和结果，删除“这里有一个影响结果的细节”“值得注意的是”“下面介绍一个功能”等预告式引导语。实际条件、影响和边界直接接在功能后，不用先评价这件事有多重要。
- 不强求每句主谓宾齐全。上下文清楚时，适当省略重复的主语、宾语或限定词，简化“进行分析”“能够支持导出”等动词结构。保留事实、条件、归属及“可以／应／必须”等语义强度，不机械压成碎句。
- 平实陈述，删除装饰性词藻、设问、反问、无必要转折及“不是……而是……”铺垫。避免机械排比、连续口号、每段总结。
- 解释框架和核心机制，必要时只展开一段核心代码。安装命令单独保留，完整实现进入复现材料。
- 表格用于功能差异、设备条件和实测结果。数字有出处与适用范围，一次耗时不能变成普遍性能结论。
- 不以日期、Trending 或 Star 开篇。不写使用哪种助手、AI CLI、写作技能或图片工具；被评项目自身的 CLI／API／模型可以介绍。
- 不堆砌“只是演示”“没有公网部署”“未测试全部功能”。修补后的行为、设备限制、素材实际展示范围等影响操作和结论的条件仍需简洁说明。
- 封面可以有冲击力，不能新增未经验证的速度、相似度、免费范围或收益承诺。

例如，删掉“这里有一个影响结果的细节”，直接写：

> **分析日期与行情日期分别处理。** 周末强制运行时，输入注明非交易日，标出上一完整交易日。模型应基于已有日线解释走势，避免把周五数据写成周日盘中变化。

## 无跳转链接

不用 Markdown 跳转链接、HTML 锚点、裸 URL 自动链接或编号外链。完整项目地址在开头用纯文本／行内代码；安装命令里的地址保留。

移除链接时保留用途：安装指南变为前提和操作；文档链接变为具体机制说明；附件链接变为与读者有关的摘要；音频链接变为直接播放器。不留下“详见这里”。来源及素材对应关系进入 evidence/。

## Humanizer-CN

上游：`https://github.com/AlexBybye/humanizer-CN`。核实本次可获得的最新版并读取实际 SKILL.md，按需读取条件模式。同一轮已核实且只做小改时复用，不重复联网。无法核实更新时采用缓存并如实说明。

先处理结构重复，再润色句子，最后对照事实、数字、归因、条件和指定原文。用户风格优先于通用规则，不为了“人味”增加虚构体验、情绪或问句。技能版本与过程仅放内部记录。

## 文末与品牌资产

默认互动文案如下；用户提供了固定文案时原样保留。此处的问句与表情是局部例外。

```text
💬 你用过哪款 AI 工具？欢迎评论区分享你的体验！

⭐ 觉得有用？点个「在看」让更多开发者看到这篇文章！
```

默认不插入二维码、公众号名称或他人的品牌图片。用户提供二维码后，使用同源本地副本或资源内嵌，宽 100 px、居中、保持纵横比；不能被全局 width:100% 拉宽，不包裹跳转链接。用户给出新文末时按新要求执行。
