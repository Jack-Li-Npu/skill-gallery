# 开源项目实测图文

这套工作流用于开源项目实测图文。面向有技术基础的读者，交付可直接阅读和发布的成稿。最新用户要求优先于以下默认偏好。

## 本次范围

- 给了项目就围绕该项目工作；只修改配图或段落时，完成该修改并同步相关导出，不重跑部署、改写全文或改动已认可的图片。
- 要求从 GitHub Trending 选题时，核实当前榜单与项目，优先选择现有设备可运行、有实际价值且能展示结果的项目。选择依据保存在证据中，不用榜单日期、Star 数或热度作文章开头。
- 写作、调研和操作由当前 Codex 完成，不委派其他代理，不接入额外付费模型 API。产品必需的本地模型属于运行依赖；配图使用已授权的内置图像工具。新增收费服务或公开部署不从写稿推定授权。
- 默认由用户提交文章；本技能不自动发布、发帖、发消息或创建定时任务。

## 工作路径

1. 阅读官方说明、稳定版本、关键源码和设备要求，先查找 README、Quickstart、examples/demo 目录及官方展示中的推荐示例。优先按原步骤实际运行有代表性的官方示例，理解项目最有辨识度的能力；没有合适示例时，再自行设计任务。示例选择与补充规则见 [cases-and-visuals.md](references/cases-and-visuals.md)。复用已有环境、服务、模型缓存与素材。
2. 完成安装、开始使用与端到端任务。核对输出完整性、参数生效和结果复用，不能凭启动成功或 HTTP 200 宣称测试完成。必要修补保留最小补丁与复现步骤。
3. 每篇完整项目文章必须检索外部使用记录，核实至少一个有具体过程和结果素材的社区案例；标准与材料缺口处理见 [cases-and-visuals.md](references/cases-and-visuals.md)。内部 evidence/ 保存版本、配置、输入、日志、输出和来源，分清官方能力、本机实测、社区自述与扩展设想。
4. 写作前读 [editorial.md](references/editorial.md)，先确定目标读者的具体处境、情绪和项目能提供的实际帮助，再按“概览 → 部署与开始使用 → 实战与使用案例 → 结语”组织。使用核实过的最新版 AlexBybye/humanizer-CN；无法确认更新时说明采用缓存，不声称最新。
5. 先写完整的项目介绍，确认标题、核心机制和有依据的结果，再据此设计正文首图与两种公众号封面。提示词必须带入介绍正文和相关事实；标题突出，画面表达具体内容，风格与布局按项目变化。具体信息提取、提示词与尺寸要求见 [cases-and-visuals.md](references/cases-and-visuals.md)。
6. 按 [delivery.md](references/delivery.md) 用实际 doocs/md 引擎或编辑器导出 Markdown、三种字体和图文包。首次使用或迁移环境时读 [workspace.md](references/workspace.md)，先确认当前工具和输出位置。

核心路径遇到问题先解决能够解决的部分，交付中简明说明真实完成状态。

## 必须保留的编辑决策

- 标题和首图先让目标读者认出自己的处境，再落到项目的具体用途。共鸣、调侃和用户提供的梗图可作切入，功能与效果必须有事实支持。项目介绍与开始使用是主体，案例位于后部。解释组件职责、数据流和一项核心设计，不把文章写成单个案例的教程。
- 使用具体数字和陈述句，直接写功能、行为和结果；上下文清楚时可省略句子成分。删掉词藻、问句、无信息铺垫、不必要转折、空泛评价和重复总结。保留短安装命令，核心设计代码至多展开一段。
- 文章排版、配图和自建示例减少不必要的次级标签、副标题、图注和重复说明，让布局承担解释。优先用层级、分组、对齐、留白及位置关系表达结构；文字只补充视觉无法清楚传达的事实、条件和操作信息，保留必要的组件名称与控件标签。
- 正文不出现代为操作的助手、AI CLI、写作技能、制作过程或“项目与制作说明”。保留影响选型和操作的限制，不堆砌自我辩护式说明。
- 正文无跳转链接。开头显示项目完整纯文本地址；链接中的有效信息就地概括，完整出处保存在内部证据。图片、播放器和安装命令不包裹跳转链接。
- 第二章集中列系统、硬件、磁盘、内存／显存、驱动及必要设置，区分官方要求与实际测试配置。
- 配图在介绍成文后生成。正文首图用视觉关系展开项目机制与应用，中文标题保持主视觉；公众号宽版与方版分别重排，按缩略图可读性取舍细节。不固定封面配色和布局。架构图全英文，不加整体标题或副标题。截图展示真实状态。
- 社区案例自然写“有博主测试”“有开发者做了”，不列平台、账号、姓名或原帖链接。不用一句“成功了”代替结果展示，不把他人测试写成本机实测。
- 文末采用 editorial.md 的默认互动文案或用户指定原文；二维码仅使用用户提供的资产，默认不插入。指定文末是通用“无问句”偏好的局部例外。

不机械套用“原字数的三分之二”、固定图片数或某次设备门槛。先保证介绍、上手和结果完整，再删重复。新修正更新对应参考，不积累互相矛盾的规则。
